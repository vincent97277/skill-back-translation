# 回譯練習的共用邊界（討論稿）

日期：2026-10-15。以下是待選擇的方案，不是已實作的跨 skill API，也不是已確認的長期保存能力。

討論進度：使用者已接受 Q8 的單一核心、兩種入口與 plugin 作為後續封裝層。Q9 保存與追蹤需求尚未理解，仍待澄清；下列保存提案不可視為已獲接受。

後續結果：使用者澄清後選擇「這版先做單次練習」。本稿保留原討論選項，正式決策以 [共用邊界決策](../../.scratch/back-translation/issues/05-reuse-boundary.md) 為準；本版不要求跨聊天摘要或長期保存。

## 候選方案：一套教學核心，兩種進入方式

**獨立練習**：使用者提供英文，從理解原文與選擇英翻中路徑開始，完成回譯、回饋與再運用。

**其他流程中的練習**：例如文章閱讀流程先選定兩句與語境，再交接到同一套回譯規則；如果已有核定中文或使用者回譯稿，只補齊缺少的步驟，避免重做。完成後以短摘要銜接回原流程。這是對話層次的交接需求，不假設平台提供可程式呼叫的 skill 函式。

教學規則只保留一套；各入口不複製不同版本的糾錯分類與回饋標準。先以 skill 承載教學流程，之後可由 plugin 與其他相關 skill 一起封裝。這是本案候選封裝策略，能力依據見 [官方文件查核](../research/skill-plugin-boundary.md)。

## 交接材料

| 材料 | 最小需求 |
| --- | --- |
| 英文原文 | 必須有；缺少時先補齊，不能杜撰原文來做比較 |
| 語境與出處 | 若會影響解讀則需保留；無法確認的背景不自行補成事實 |
| 中文提示 | 可選；沿用前須確認與原文對應，不能只因另一流程提供就視為一定正確 |
| 學習者回譯稿 | 可選；只能把真正的使用者作答視為學習表現 |
| 已完成步驟 | 有可見依據才沿用；缺少時先補所需內容，不假裝已完成 |
| 本輪偏好 | 可選，例如剩餘時間、特定想練的表達或希望簡短；無設定就使用已確認的教學預設 |

## 完成後交接什麼

保留本輪材料、原始作答與修訂的對應關係，供當前對話繼續使用；對外只需一個短摘要：

- 練了哪個表達或判斷，例如 be used to + V-ing。
- 學習者實際完成了什麼，例如在提示後自行修正、在新情境成功使用。
- 仍卡住什麼或下一次值得再試的提示；未實際作答則明確留為未觀察。

例如：「本輪練 be used to + V-ing；提示後能改正原句，新情境自行用對一次；尚未觀察延後保留。」不給未經測量的能力分級，也不把本次成功寫成永久掌握。

## 保存需求的候選邊界

建議初版先依當前對話可用的上下文延續，並按需要提供可攜的練習摘要。跨聊天時可帶入摘要；沒有摘要或必要材料時先補齊。

是否自動寫入本機學習檔案、建立題庫或做跨聊天複習追蹤，需要另行選擇；不由 skill 存在本身推論已具備。當前不要求外部服務，也不自動把未授權的學習資料交給其他聊天或應用。

## 目前待使用者決定

1. 已確認：單一回譯 skill 核心，支援獨立與其他流程交接兩種入口，plugin 作為後續封裝層。
2. 待澄清：是否只設計每次的練習，或同時設計一份可保存的學習紀錄，讓下次能針對舊問題複習？「摘要」只是把本次練習寫成幾行筆記；若無自動保存方案，使用者想在另一段聊天接續時須自行提供這份筆記。
